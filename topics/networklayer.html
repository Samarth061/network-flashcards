Core concepts at a glance

Forwarding
Router-local: move packet from input link to correct output link
Routing
Network-wide: determine end-to-end paths (via routing algorithms)
Internet service model
Best-effort: no guarantees on delivery, order, timing, or bandwidth
VC network
Connection-oriented at network layer; routers maintain VC state
Datagram network
Connectionless; each packet routed independently; Internet uses this
Longest prefix match
When multiple forwarding table entries match, use the most specific (longest) prefix

NAT translation table (how it works)

Host 10.0.0.1:3345 → Web server 128.119.40.186:80
NAT router replaces src with WAN IP + new port: 138.76.29.7:5001
Adds entry: WAN 138.76.29.7:5001 ↔ LAN 10.0.0.1:3345
Reply arrives to 138.76.29.7:5001 → NAT looks up table → rewrites dst to 10.0.0.1:3345
Port field = 16 bits → over 60,000 simultaneous connections per public IP

Queueing & buffer sizing

Classical buffer rule
B = RTT × C (e.g., 10 Gbps × 250ms = 2.5 Gbits)
Modern buffer rule
B = RTT × C / √N where N = number of TCP flows
HOL blocking
Input-queued switch: head-of-line packet blocks packets behind it even if their output is free. Limits throughput to 58% of capacity.
Drop-tail vs AQM
Drop-tail drops arriving packet when full. AQM (e.g., RED) proactively marks/drops before full to signal congestion early.

BGP key attributes

AttributePurpose
AS-PATHList of ASes the advertisement has traversed. Used to detect loops (reject if own AS in path) and choose shorter paths.
NEXT-HOPIP address of the first router outside the current AS along the advertised path. Links inter-AS and intra-AS routing.
Local PreferenceSet within an AS to prefer one exit point over another. Higher = preferred. Policy-based.
BGP route selection order: (1) highest Local Preference → (2) shortest AS-PATH → (3) hot-potato routing (closest NEXT-HOP) → (4) BGP identifiers
