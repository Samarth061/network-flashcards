Section 1

Introduction to the Network Layer

What does the network layer do, and how does it do it?

Every time you visit a website, data travels across dozens of routers in milliseconds. The network layer is the layer of the protocol stack responsible for getting packets from a source host to a destination host across this complex web of routers and links.

Unlike the transport and application layers, which exist only in end systems, the network layer exists in every host and every router in the network. This makes it one of the most challenging layers to design.

Forwarding vs. Routing — The Most Important Distinction

The network layer has two core functions that are often confused. They are fundamentally different:

Forwarding vs Routing

Forwarding (Data Plane)

When a packet arrives at a router's input link, the router looks at the packet's header and moves it to the correct output link. This is a local, per-router action. Think of it as getting through a single highway interchange.

Routing (Control Plane)

The network-wide process of determining the path from source to destination across many routers. Routing algorithms compute the forwarding tables that forwarding uses. Think of it as planning your entire road trip before you leave.

Key insight: Routing algorithms determine what values go into forwarding tables. Forwarding uses those tables to move packets. The two functions are tightly coupled but distinct. You could theoretically have a human manually fill forwarding tables (no routing algorithm needed!) — but it would be slow and error-prone.

Network Service Models

What kind of service does the network layer promise to deliver? Different network architectures make different promises:

The Internet's best-effort model makes no guarantees about delivery, ordering, timing, or bandwidth. While this sounds terrible, it has a crucial advantage: it places minimal requirements on the network infrastructure, making it easy to interconnect wildly different link technologies (satellite, Ethernet, fiber, radio). All the "smart" reliability logic lives in end systems (TCP), not the network core.

Section 2

Virtual Circuit vs. Datagram Networks

Two fundamentally different ways to move packets through a network

Just as the transport layer can offer connection-oriented (TCP) or connectionless (UDP) service, the network layer can do the same. This gives us two fundamentally different network architectures:

Virtual Circuit (VC) Networks

In a VC network, before any data flows, a connection (the virtual circuit) must be established end-to-end. Each router along the path sets up state for this connection. The Internet does not use VCs, but ATM and Frame Relay do.

Virtual Circuit: Path A → R1 → R2 → B (VC numbers on each link)

A VC has three phases:

1
VC Setup

Path determined, VC numbers assigned to each link, forwarding table entries added at every router along the path. Resources (bandwidth) may be reserved.

2
Data Transfer

Packets carry the VC number in their header. Each router translates the VC number using its forwarding table and forwards to the next hop.

3
VC Teardown

All forwarding table entries along the path are removed. VC no longer exists.

Why do VC numbers change at each link? Two reasons: (1) Shorter VC numbers are sufficient if they're only link-local. (2) It simplifies setup — each link can independently choose any locally unused number without coordinating globally.

Datagram Networks

The Internet is a datagram network. There is no connection setup. Each packet carries the destination IP address and is forwarded independently. Routers don't maintain per-connection state — just destination-based forwarding tables.

Longest Prefix Matching — How Datagram Forwarding Works

Longest Prefix Matching: When multiple entries in the forwarding table match a destination address, the router always uses the most specific (longest) match. A /24 prefix beats a /20 prefix, even if both match. This is what allows ISPs to advertise aggregated routes while organizations can advertise more specific sub-blocks.

Section 3

What's Inside a Router?

The hardware and software architecture that makes packet forwarding possible

A router has four main components. Think of a busy traffic roundabout: cars enter from one road, a station attendant looks up where they're going, they cross the roundabout, and leave via the right exit road.

Router Architecture — Control Plane vs Data Plane

The Three Switching Fabrics

The switching fabric is the heart of the router — it physically moves packets from input to output. Three approaches exist:

Three Switching Fabric Approaches

Queueing and Packet Loss

Queues form at both input and output ports. When memory fills up, packets are dropped — this is where packet loss actually happens in routers.

Head-of-Line (HOL) Blocking — A critical problem in input-queued switches: a packet at the head of an input queue that can't move (its output is busy) blocks all packets behind it, even if those packets' outputs are free. HOL blocking limits throughput to just 58% of link capacity.

Buffer sizing: The old rule was B = RTT × C (e.g., 2.5 Gbits for a 10 Gbps link with 250ms RTT). Modern research shows B = RTT × C / √N when N large TCP flows share the link — buffers can be much smaller.

Section 4

The IPv4 Datagram

The fundamental unit of data in the Internet

Every packet sent across the Internet is an IPv4 datagram. Understanding its format is essential — this is what routers actually look at and manipulate.

IPv4 Datagram Header Format (32 bits wide)

Let's walk through each key field:

Version4 bitsIP version number. Set to 4 for IPv4, 6 for IPv6.
IHL4 bitsInternet Header Length — header size in 32-bit words. Minimum = 5 (= 20 bytes). Needed because options make the header variable-length.
Type of Service8 bitsQoS marking. First 6 bits = DSCP (Differentiated Services Code Point for traffic priority). Last 2 bits = ECN (congestion notification).
Datagram Length16 bitsTotal length of the datagram (header + data) in bytes. Max = 65,535 bytes. In practice, rarely exceeds 1,500 bytes due to Ethernet MTU.
Identifier16 bitsUnique number assigned by the sender. All fragments of the same original datagram share the same identifier.
Flags3 bitsBit 1 = DF (Don't Fragment). Bit 2 = MF (More Fragments — set on all fragments except the last). Bit 0 = reserved.
Fragment Offset13 bitsPosition of this fragment's data within the original datagram. Measured in units of 8 bytes.
TTL8 bitsTime-to-Live — decremented by 1 at each router. When it reaches 0, the packet is discarded and an ICMP "TTL Expired" is sent back. Prevents packets from looping forever.
Protocol8 bitsUpper-layer protocol: TCP=6, UDP=17, ICMP=1, OSPF=89. Tells the destination which protocol to hand the payload to.
Header Checksum16 bitsError detection for the header only. Must be recomputed at every router because the TTL changes at each hop.
Source / Destination IP32 bits eachSender's and receiver's IP addresses. Technically assigned to interfaces, not hosts — a router with 3 links has 3 IP addresses.
Section 5

IP Fragmentation

What happens when a packet is too big for the next link

Different link technologies support different Maximum Transmission Unit (MTU) sizes — the largest frame payload they can carry. Ethernet supports up to 1,500 bytes. Some WAN links support only 576 bytes. When a datagram is larger than the next link's MTU, it must be fragmented.

Fragmentation: 4,000-byte datagram through 1,500-byte MTU link

Security risk: Fragmentation has been exploited for DoS attacks. The "Jolt2" attack sends a stream of small fragments with no offset-zero fragment, causing the target to crash trying to reassemble them. IPv6 eliminates router-level fragmentation entirely to avoid these problems.

Section 6

IPv4 Addressing and CIDR

How devices get addresses, how networks are organized, and how routers find destinations

An IPv4 address is a 32-bit number written in dotted-decimal notation (e.g., 193.32.216.9). There are 2³² ≈ 4.3 billion possible addresses. Crucially, an IP address is assigned to an interface (a router's link), not to the device itself — a router with 3 links has 3 different IP addresses.

Subnets

Devices whose IP addresses share the same leftmost bits form a subnet. The shared portion is called the subnet address, written as a.b.c.d/x where x is the number of shared bits.

Subnets: Devices sharing the same prefix form a subnet

CIDR — Classless Interdomain Routing

Before CIDR, addresses came in only 3 sizes: Class A (/8), Class B (/16), Class C (/24). This was incredibly wasteful — a company needing 2,000 addresses had to take a Class B (65,534 addresses) and waste 63,000 of them.

CIDR allows any prefix length. The address format is a.b.c.d/x where the top x bits are the network prefix. This enables address aggregation:

Address Aggregation — One ISP prefix covers all its customers

The Internet only needs one forwarding table entry for 200.23.16.0/20 to reach all 8 organizations. This is address aggregation (also called route summarization), and it's what keeps the global routing table manageable.

How to find subnets: Detach each interface from its host or router, creating isolated islands. Each island is a subnet. A router with 3 interfaces connecting 3 different subnets is part of 3 different subnets simultaneously.

Section 7

DHCP — Getting an IP Address Automatically

The plug-and-play protocol that configures hosts automatically

When you connect your laptop to a new network, it automatically gets an IP address, default gateway, subnet mask, and DNS server address. This magic is DHCP (Dynamic Host Configuration Protocol).

DHCP 4-Step Handshake

DHCP provides: IP address · subnet mask · default gateway · DNS server address · lease duration. Why are all four messages broadcast? The client doesn't know the server's address yet, and the server doesn't know the client's IP yet — so both sides must broadcast.

Section 8

NAT — Network Address Translation

How millions of home networks share a single public IP address

There are only ~4.3 billion IPv4 addresses, but billions of devices need to be on the Internet. NAT solves this by allowing an entire home network (using private addresses like 10.0.0.x) to share a single public IP address.

NAT in Action — One Public IP, Multiple Private Hosts

NAT Criticisms: (1) Port numbers are meant to address processes, not hosts. (2) Routers should only process up to Layer 3, not touch ports. (3) Violates the end-to-end principle. (4) Breaks P2P applications — a host behind NAT can't accept incoming TCP connections. (5) The "right" fix is IPv6 with more addresses.

ICMP — Internet Control Message Protocol

How the network reports errors and how ping & traceroute work

ICMP lets routers and hosts communicate network-layer information — primarily error reports. ICMP messages are carried inside IP datagrams (they're IP payload, not a separate protocol).

How Traceroute Works

1
Send datagram with TTL=1

First router receives it, decrements TTL to 0, discards it, sends back ICMP Type 11 (TTL Expired) with its own IP and name. Source records the router identity and RTT.

2
Send datagram with TTL=2

Reaches the second router, same process. Source now knows the 2nd hop.

3
Continue incrementing TTL

Eventually a datagram reaches the destination. Since the UDP port number is intentionally "unlikely," the destination sends back ICMP Type 3 Code 3 (Port Unreachable).

4
Stop when Port Unreachable received

Source now has the identity and RTT for every router on the path. Sends 3 probes per TTL value.

Warning: Firewalls that block ICMPv6 break Path MTU Discovery in IPv6 — packets get silently dropped and the sender never learns the correct MTU. Always allow "Packet Too Big" ICMPv6 messages through firewalls.

Section 10

IPv6

The next generation IP — why it exists and what changed

IPv4's 32-bit address space was running out. In February 2011, IANA allocated the last unassigned IPv4 blocks. IPv6 was designed in the early 1990s to fix this and take the opportunity to clean up other IPv4 issues.

IPv6 Header (fixed 40 bytes) vs IPv4 (variable, min 20 bytes)

IPv4 → IPv6 Transition Strategies

Dual-Stack

Nodes implement both IPv4 and IPv6 and choose based on the peer. Problem: if an IPv4-only router is in the path, IPv6-specific fields (like the flow label) are lost in conversion.

Tunneling

The entire IPv6 datagram is wrapped inside an IPv4 datagram's payload to cross IPv4-only infrastructure. The IPv6 datagram arrives intact at the other end of the tunnel.

How routers collectively figure out the best paths

A routing algorithm's job: given a network modeled as a graph where nodes are routers and edges are links with costs, find the least-cost path from a source router to every other router.

Network modeled as a weighted graph

Section 12

Link-State Routing — Dijkstra's Algorithm

When every router knows the complete network map

In link-state routing, every router broadcasts its link-state (which neighbors it's connected to, and the cost of each link) to every other router in the network. After this broadcast, every router has a complete, identical map of the network. Each router then independently runs Dijkstra's algorithm to compute shortest paths to all destinations.

// Dijkstra's Shortest Path Algorithm (from source node u) Initialize: N' = {u} // set of nodes with known shortest path D(v) = c(u,v) for each neighbor v // initial cost estimates D(v) = ∞ for all non-neighbors Loop: w = node NOT in N' with minimum D(w) // find cheapest unvisited node add w to N' for each neighbor v of w, v not in N': D(v) = min( D(v), D(w) + c(w,v) ) // relax edge until N' = N (all nodes visited)

Worked Example (from the book)

Network: u is source, with neighbors v (cost 2), x (cost 1), w (cost 5). Step-by-step:

StepN'D(v), p(v)D(w), p(w)D(x), p(x)D(y), p(y)D(z), p(z)
Initu2, u5, u1, u∞∞
1u, x2, u4, x—2, x∞
2u, x, v—3, y——4, y
3u, x, v, y—3, y——4, y
4u, x, v, y, w————4, y
5all—————

At step 1, we add x (cheapest unvisited, cost 1). Going through x, we discover v is still 2 via u, w improves to 4 (1+3), and y is 2 (1+1). Complexity: O(n²), or O(n log n) with a heap.

Oscillation problem: If link costs are based on traffic load, all routers can simultaneously shift to the same uncongested path, instantly congesting it, then all shift back — creating oscillations. Fix: randomize the time each router sends link-state advertisements so they don't all run LS simultaneously.

Section 13

Distance-Vector Routing

Distributed routing where each node only knows its neighbors

In DV routing, each node only knows the costs to its directly connected neighbors. Nodes iteratively exchange their distance vectors (cost estimates to all destinations) with neighbors. Over time, the estimates converge to the true shortest paths via the Bellman-Ford equation.

Bellman-Ford Equation: dx(y) = minv { c(x,v) + dv(y) }

The shortest path from x to y = the minimum over all neighbors v of (cost to reach v) + (v's shortest path to y). This is the mathematical foundation of DV routing.

The Count-to-Infinity Problem

DV routing has a critical flaw when link costs increase (or links fail). Consider this scenario:

Count-to-Infinity: Link x-y cost increases from 4 to 60

The fix is Poisoned Reverse: if z routes to x through y, z advertises D_z(x) = ∞ to y (a "white lie"). This prevents y from thinking it can route back to x via z. However, poisoned reverse only prevents 2-node loops — 3-or-more-node loops still cause count-to-infinity.

Section 14

Hierarchical Routing — Autonomous Systems

Solving the scaling and administrative autonomy problems

Running a single routing algorithm across the entire Internet (hundreds of millions of routers) is impossible — the routing table alone would be enormous and routing messages would consume all bandwidth. Two solutions are needed:

Scale Problem

A single DV algorithm with 100M+ nodes would never converge. A single LS broadcast would consume all bandwidth. Solution: group routers into smaller domains.

Administrative Autonomy

Different companies, ISPs, and governments want to run their own routing protocols and hide their internal topology. Solution: allow each domain to run its own protocol.

The solution: organize routers into Autonomous Systems (ASes). Each AS runs its own intra-AS routing protocol. Between ASes, a single inter-AS protocol (BGP) operates.

Autonomous Systems: Intra-AS (IGP) vs Inter-AS (BGP)
Section 15

RIP — Routing Information Protocol

The simplest Internet routing protocol

RIP is one of the oldest Internet routing protocols, still used in small enterprise and lower-tier ISP networks. It is a pure distance-vector protocol using hop count as its metric.

Key Properties

  • Metric: hop count (each link = 1 hop)
  • Maximum hops: 15 (16 = infinity)
  • Updates every 30 seconds
  • Neighbor considered dead after 180 seconds of silence
  • Uses UDP port 520
  • Each advertisement: up to 25 destination subnets

Limitations

  • Max network diameter: 15 hops
  • Slow convergence (DV algorithm)
  • Count-to-infinity problem
  • No authentication (v1)
  • Only hop count — ignores bandwidth

RIP is implemented as an application-layer daemon (routed) running over UDP — an unusual design where a routing (network-layer) protocol is actually implemented as an application. This is because it can use standard OS sockets and UDP transport without requiring kernel modification.

Section 16

OSPF — Open Shortest Path First

The link-state protocol used by major ISPs

OSPF is the successor to RIP and is widely used in upper-tier ISPs. It is a link-state protocol — each router floods its link costs to all other routers in the AS, then every router independently runs Dijkstra's algorithm.

Key Advances Over RIP

  • Security: OSPF messages can be authenticated with MD5 hashes. Without authentication, malicious routers could inject false routing information into the network.
  • Multiple equal-cost paths: OSPF can load-balance across all paths that have the same cost — RIP can only use one.
  • Hierarchical areas: An AS can be organized into areas (see below). Each area runs Dijkstra internally. Only summary information crosses area boundaries.
  • OSPF runs directly over IP (protocol 89, not UDP/TCP), and implements its own reliable flooding mechanism.
OSPF Hierarchical Areas

Routing within an area uses the full link-state database for that area. Routers in Area 1 don't need to know the detailed topology of Area 2 — they only need the summary routes advertised by the Area Border Routers (ABRs).

Section 17

BGP — Border Gateway Protocol

The protocol that glues the Internet together

BGP is the only inter-AS routing protocol used in the real Internet. It's what allows your traffic to cross from your ISP's network to YouTube's network. BGP is a path-vector protocol — a variant of DV where advertisements carry the full AS-PATH (preventing loops).

eBGP vs iBGP

eBGP (External BGP)

BGP sessions between routers in different ASes. Used to learn which prefixes are reachable via neighboring ASes. Runs over TCP port 179.

iBGP (Internal BGP)

BGP sessions between routers in the same AS. Distributes eBGP-learned routes to all routers within the AS. Requires a full mesh (every router to every other) or route reflectors.

BGP Route Selection (in order)

1
Highest Local Preference

Set by network administrators to enforce policy — e.g., "prefer routes through Provider A over Provider B." Economic/contractual decisions dominate.

2
Shortest AS-PATH

Among routes with the same local preference, prefer the one that traverses the fewest ASes. This is essentially a DV algorithm at the AS level.

3
Hot-Potato Routing (closest NEXT-HOP)

Among routes with the same AS-PATH length, prefer the one whose NEXT-HOP router has the lowest intra-AS cost. Get rid of the packet (the "hot potato") as cheaply as possible.

4
BGP Identifiers

Final tiebreaker using router identifiers.

Why different inter-AS and intra-AS protocols?
Policy: Inter-AS is dominated by economic/political relationships (e.g., ISP A won't carry transit traffic for free for ISP B). BGP's path attributes enable fine-grained control. Intra-AS just optimizes performance.
Scale: BGP must handle the entire Internet. OSPF/RIP only need to handle one AS.
Performance: Intra-AS cares about performance. Inter-AS may deliberately take a suboptimal path to satisfy policy.

Section 18

Broadcast Routing

Delivering one packet to all nodes in the network

Broadcast means sending a packet from one source to all nodes. The naive approach (N-way unicast: send N separate copies) is inefficient and requires knowing all destination addresses. Better approaches let routers duplicate packets:

Broadcast Approaches — from naive to optimal

Spanning Tree broadcast is optimal but requires constructing and maintaining the tree. The center-based approach builds it by having nodes send unicast tree-join messages toward a designated center node; the paths they follow become the tree branches.

Section 19

Multicast Routing

Delivering one packet to a specific subset of nodes

Multicast delivers a packet to a specific group of nodes (not all, not just one). Applications: live video streaming, software distribution, conferencing. A Class D IP address (224.0.0.0/4) identifies a multicast group.

IGMP — Joining a Multicast Group

IGMP operates between a host and its directly attached router. It has three message types:

  • membership_query: Router → all hosts on link; asks which multicast groups are active
  • membership_report: Host → router; declares it's in a multicast group (also sent spontaneously when joining)
  • leave_group: Optional. Router infers departure if host stops responding to queries — this is soft state

Multicast Routing Trees

Group-Shared Tree

One tree for all senders in the group. Built using the center-based approach (same as spanning tree broadcast). All traffic flows through the center/rendezvous point. Used by PIM sparse mode.

Source-Specific Tree

Separate tree for each sender. Uses RPF algorithm from the source, then prunes branches leading to routers with no group members. Used by DVMRP and PIM dense mode.

Pruning: In source-specific trees, a router that has no group members sends a prune message upstream. If all downstream routers prune, the upstream router can also prune — cleaning up the tree to only include branches with actual group members.

In the Internet today: PIM (Protocol Independent Multicast) is the most widely used multicast routing protocol. PIM dense mode uses flood-and-prune. PIM sparse mode uses rendezvous points for group-shared trees. IP multicast has not achieved widespread deployment — most streaming uses application-layer multicast (CDNs, P2P) instead.
